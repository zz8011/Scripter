# 一、产品概述

## 1.1 产品愿景

> **"剧灵，让每个有故事的人都能成为编剧"**

剧灵是一个面向所有有创作梦想的人的 AI 编剧创作平台。通过深度集成的 AI 伙伴系统，我们帮助用户从灵感到成品，完成完整的剧本创作旅程。

**核心理念**:
- 🤝 **AI 是创作伙伴，不是工具** — 共创而非替代
- 🌱 **创作民主化** — 消除技术门槛，让创意落地
- ✨ **硅基碳基共生** — 体验人机共创带来的全新可能

## 1.2 目标用户

| 用户类型 | 占比 | 核心需求 | 支付意愿 |
|---------|------|---------|---------|
| **业余创作者** | 40% | 降低门槛、实现梦想 | 低-中 |
| **独立编剧** | 30% | 效率工具、专业提升 | 中-高 |
| **编剧新人** | 20% | 学习引导、快速入门 | 中 |
| **专业团队** | 10% | 协作、版本管理 | 高 |

# 二、功能需求

## 2.1 功能模块架构

```
剧灵 Scripter
├── 创作空间 (Creative Space)
│   ├── 灵感捕捉 (Inspiration Capture) - 随手记、语音转文字
│   ├── 剧本编辑器 (Script Editor) - TipTap 富文本、格式检查
│   └── 阅读模式 (Reader Mode) - 沉浸式阅读、AI 注释
│
├── AI 创作伙伴 (剧灵 Juling)
│   ├── 生辰八字系统
│   │   ├── 用户注册时间生成八字
│   │   ├── 五行性格决定说话风格
│   │   ├── 诗号生成
│   │   └── 用户可自定义剧灵名字
│   ├── 交互系统
│   │   ├── 不打扰原则 - 创作时静默观察
│   │   ├── 相关性判断 - 智能注入上下文
│   │   └── 行为记录 - 全模块关键动作
│   ├── 原子化技能 (Skills)
│   │   ├── 格式修复、对白润色、场景扩展
│   │   ├── 节奏分析、一致性检查、人性化转换
│   │   └── 集长计算
│   └── 对话模式
│       ├── 对话式 - 自由交流讨论
│       ├── 共创式 - 你一句我一句
│       └── 反馈式 - 基于上下文的建议
│
├── 项目管理 (Project Management)
│   ├── 仪表板 - 项目概览、进度追踪
│   ├── 项目创建向导 - 引导式设置
│   └── 创作进度追踪 - 里程碑管理
│
├── 创作资源 (Creative Resources)
│   ├── 人物管理 (Characters) - 档案卡片、小传编辑
│   ├── 场景管理 (Scenes) - 看板视图、拖拽排序
│   ├── 世界观 (Worldview) - 多维设定编辑
│   └── 分镜 (Storyboard) - 四栏排版、运镜建议
│
└── 导出与分享 (Export & Share)
    ├── 多格式导出 - PDF/Word/Text/纯图PDF
    ├── 制作准备文档 - 角色清单、场景列表
    └── 协作分享 - 链接分享、权限控制
```

## 2.2 MVP 功能范围

| 模块 | 功能 | 验收标准 |

# 三、技术栈

## 3.1 核心技术

| 层级 | 技术 | 版本 | 说明 |
|------|------|------|------|
| **前端框架** | Next.js | 14+ | App Router, SSR/SSG |
| **UI 组件** | shadcn/ui + Tailwind CSS | latest | 纸质主题 (#F5F1E8 + #C9A962) |
| **编辑器** | TipTap | latest | 无头设计、高度可定制 |
| **AI 文本** | 智谱 GLM-4.7 | - | 国产大模型、成本更低 |
| **AI 图片** | T8Star (nano-banana-2) | - | 专业图片生成服务 |
| **数据库 ORM** | Drizzle ORM | latest | 高性能、SQL 透明、Edge 支持 |
| **数据库** | PostgreSQL | 15+ | 关系型数据库 |
| **认证** | Casdoor | latest | 独立部署、可视化管理、SSO |
| **拖拽** | @dnd-kit/core | latest | 现代化拖拽库 |
| **存储** | AWS S3 / 阿里云 OSS | - | 对象存储、CDN |

## 3.2 技术选型说明

### Drizzle ORM vs Prisma

| 特性 | Drizzle | Prisma |
|------|--------|--------|
| 性能 | ⚡ 快（无查询解析开销） | 中等 |
| 包大小 | ~100KB | ~3MB |
| SQL 控制 | ✅ 显式、透明 | 隐式抽象 |
| Edge Runtime | ✅ 完全支持 | ❌ 不支持 |

**决策**: Drizzle 提供更好的性能和 SQL 透明度，完全支持 Edge Runtime。

### Casdoor vs NextAuth.js

| 特性 | Casdoor | NextAuth.js |
|------|---------|-------------|
| 部署方式 | ✅ 独立服务 | 应用内集成 |
| 管理界面 | ✅ 完整 Web UI | ❌ 无 |
| SSO | ✅ 内置 | ⚠️ 需自建 |
| 协议支持 | OAuth 2.0 + OIDC + SAML | OAuth 2.0 |

**决策**: Casdoor 提供企业级身份管理，可视化管理界面降低运维成本。

### 智谱 GLM-4.7 vs Vercel AI SDK

| 特性 | 智谱 GLM-4.7 | Vercel AI SDK |
|------|--------------|---------------|
| 成本 | ¥0.50/百万tokens | $30/百万tokens |
| 中文能力 | ✅ 专门优化 | 良好 |
| 国内合规 | ✅ 合规 | ⚠️ 需考虑 |
| API 稳定性 | ✅ 国内节点 | ❌ 依赖海外 |

**决策**: 成本降低 95%+，中文能力更强，国内访问更稳定。

# 四、数据模型

## 4.1 核心实体

```typescript
// 项目
interface Project {
  id: string
  name: string
  genre: string[]
  scriptType: 'movie' | 'series' | 'short-drama'
  orientation: 'landscape' | 'portrait'
  targetEpisodes: number
  currentStage: 'worldview' | 'character' | 'script' | 'optimize' | 'production'
  createdAt: Date
  updatedAt: Date
}

// 人物
interface Character {
  id: string
  projectId: string
  name: string
  poem: string // 人物诗号
  basicInfo: { age, gender, occupation, appearance }
  personality: string[]
  speechStyle: string
  behaviorPattern: string
  growthArc: string
  relationships: Relationship[]
}

// 场景
interface Scene {
  id: string
  projectId: string
  episodeNumber: number
  sceneNumber: number
  location: string
  timeOfDay: string
  intExt: string
  content: string // TipTap JSON
  duration: number // 秒
  status: 'draft' | 'completed'
}

// AI 对话历史
interface AIConversation {
  id: string
  userId: string
  projectId?: string
  agent: string // 使用的 Agent
  messages: ConversationMessage[]
  createdAt: Date
}

// 创作里程碑
interface CreativeMilestone {
  id: string
  userId: string
  projectId: string
  type: 'first_scene' | 'first_episode' | 'completed'
  achievedAt: Date
  aiContribution: number // AI 贡献度 0-100
}
```

# 六、风险分析

## 6.1 技术风险矩阵

| 风险 | 概率 | 影响 | 优先级 | 应对策略 |
|------|------|------|--------|----------|
| **AI API 成本超预算** | 中 | 高 | **P0** | 配额严格控制；分级定价；使用监控 |
| **TipTap 协作实现复杂** | 高 | 中 | P1 | MVP 阶段暂缓，使用乐观锁 |
| **移动端性能问题** | 中 | 中 | P2 | 懒加载；虚拟滚动 |
| **用户增长不及预期** | 中 | 高 | P1 | 内容营销；免费试用延长 |
| **竞品快速模仿** | 高 | 中 | P2 | 建立品牌护城河；社区运营 |
| **Drizzle ORM 学习曲线** | 低 | 低 | P2 | 团队培训；参考文档完善 |
| **Casdoor 部署复杂度** | 中 | 中 | P1 | Docker 部署；详细文档 |

## 6.2 产品风险

| 风险 | 应对策略 |
|------|----------|
| AI 替代人类的恐惧 | 强调"伙伴"定位，AI 扩展而非替代 |
| 创作同质化 | 保护用户风格，AI 只是辅助 |
| 过度依赖 AI | 引导用户保持主导权 |
| 创作质量下降 | AI + 人工审核、社区评价 |

## 6.3 技术风险应对

| 风险 | 应对措施 |
|------|----------|
| LLM 上下文限制 | 分块处理；特征提取；智能压缩 |
| 实时协作冲突 | 乐观锁；操作转换(OT) |
| 图片生成成本 | 用户配额；异步任务队列 |
| 数据库性能 | 索引优化；缓存策略 |
