### [2026-01-23] 编辑器技术选型

**背景**：需要选择剧本编辑器的实现方案

**选项**：
- **TipTap**：富文本编辑器，可扩展性强
- **Slate**：完全自定义，灵活性最高
- **Monaco**：代码编辑器，不适合剧本
- **Contentful**：过于重量级

**选择**：TipTap

**理由**：
1. 已有成熟的剧本格式扩展
2. React 生态集成好
3. 支持实时协作（未来需求）
4. 社区活跃，文档完善

**影响**：
- 需要自定义场景标题、对话、动作描述节点
- 编辑器状态管理需要特别设计
- 学习曲线中等

### [2026-01-23] 导航栏颜色决策

**背景**：左侧导航栏的颜色选择

**选项**：
- **白色**：浅色，普通，缺乏特色
- **黑色 #1A1A1A**：深色，品牌感强
- **灰色**：折中方案，平庸

**选择**：黑色 #1A1A1A

**理由**：
1. 符合品牌设计系统（参考原型）
2. 对比度高，视觉冲击力强
3. 与品牌金色 #C9A962 形成鲜明对比
4. 专业、高端的视觉感受

**影响**：
- 所有导航相关组件必须使用此颜色
- 导航文字必须是白色
- 活动状态用金色高亮
- Logo 需要适配深色背景

### [2026-01-23] 模态框宽度规范

**背景**：设置模态框的宽度选择

**选项**：
- **自适应**：根据内容调整
- **固定 600px**：较小
- **固定 700px**：中等
- **固定 800px**：较大

**选择**：固定 700px

**理由**：
1. 原型设计使用 700px
2. 适合大多数内容场景
3. 不会显得过于拥挤或空旷
4. 保持设计一致性

**影响**：
- 所有模态框必须使用 700px 宽度
- 移动端响应式使用 max-width: 90vw

### [2026-01-23] 剧本格式决策

**背景**：编辑时使用哪种剧本格式

**选项**：
- **纯中文格式（带△符号）**：符合中文短剧规范 v2.0
- **Fountain 国际格式**：国际通用，不带△
- **双模式切换**：编辑时用 Fountain，查看时用中文

**选择**：编辑时 Fountain，可选择中文视图

**理由**：
1. Fountain 是国际标准，工具支持好
2. 纯文本格式，便于版本控制
3. 中文格式作为可选视图
4. 导出时可选择两种格式

**影响**：
- TipTap 扩展基于 Fountain 定义
- 需要格式转换器
- 中文视图是展示层逻辑

### [2026-01-23] 状态管理方案

**背景**：应用状态管理选择

**选项**：
- **Zustand**：轻量级，API 简洁
- **Redux Toolkit**：功能强大，但较重
- **Jotai**：原子化状态
- **React Context**：内置，但性能问题

**选择**：Zustand

**理由**：
1. 轻量级，包体积小
2. API 简洁直观
3. TypeScript 支持好
4. 无需 Provider 包裹
5. DevTools 支持

**影响**：
- 全局状态用 Zustand
- 组件本地状态用 useState
- 服务端状态用 SWR 或 TanStack Query

### [2026-01-23] 样式方案选择

**背景**：CSS 样式管理方案

**选项**：
- **Tailwind CSS + CSS Variables**：实用优先
- **CSS Modules**：组件隔离
- **Styled Components**：CSS-in-JS
- **Vanilla Extract**：零运行时

**选择**：Tailwind CSS + CSS Variables

**理由**：
1. Tailwind 实用类开发效率高
2. CSS Variables 管理设计令牌
3. shadcn/ui 基于 Tailwind
4. 构建时清除未使用的样式
5. 小体积，高性能

**影响**：
- 设计令牌定义在 globals.css
- 组件使用 Tailwind 类名
- 特殊效果用 CSS Variables

### [2026-01-23] 字体加载策略

**背景**：中文字体加载优化

**选项**：
- **全部同步加载**：简单，但阻塞渲染
- **全部异步加载**：不阻塞，但有 FOIT
- **字体子集化**：体积小，加载快
- **系统字体栈**：无网络请求，但风格受限

**选择**：字体子集化 + 异步加载

**理由**：
1. 大幅减少字体文件体积
2. 按需加载字符集
3. 使用 font-display: swap 避免 FOIT
4. 性能与视觉平衡

**影响**：
- 使用 Google Fonts 子集化服务
- 或自建字体子集（next/font）
- 核心字符优先加载

### [2026-01-23] 数据库选择

**背景**：应用数据存储方案

**选项**：
- **PostgreSQL (Neon)**：关系型，功能完整
- **MySQL (PlanetScale)**：关系型，但分支管理特殊
- **MongoDB**：文档型，灵活
- **SQLite**：嵌入式，简单

**选择**：PostgreSQL (Neon)

**理由**：
1. 关系型数据模型更适合
2. Neon 提供无服务器体验
3. Prisma ORM 支持好
4. 可扩展性强

**影响**：
- 使用 Prisma 作为 ORM
- Schema 定义在 prisma/schema.prisma
- 数据库操作通过 Prisma Client

## 决策原则

### 如何做决策

1. **明确问题**：首先清晰定义要解决的问题
2. **列出选项**：找到所有可行的方案
3. **评估优劣**：每个选项的优缺点
4. **考虑约束**：项目限制、团队技能、时间成本
5. **做出选择**：选择最平衡的方案
6. **记录决策**：在此文档中记录

### 修改决策

如果需要修改之前的决策：

1. **审查原决策**：理解当初为什么这样选择
2. **识别变化**：什么条件发生了变化
3. **重新评估**：基于新条件重新评估
4. **更新记录**：在此文档中添加修改记录
